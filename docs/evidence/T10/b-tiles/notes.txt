T10 step b: procedural tiles and emblems, portrait framing fix (2026-10-11, builder)

What changed (Game and Tooling code only; Core untouched):
- Tiles: one rounded slab per tile with a flat emblem on top, built in code by Game/Match/TileMeshes.cs. Nothing is imported
  or generated by a tool (D13). Submesh 0 is the slab (symbol colour); submesh 1 is the emblem (its own shared material).
- Seven emblems, one per shape: circle, square, triangle, diamond, star, plus, hexagon. Symbol s uses shape s % 7.
  Emblem ink is dark (0.10, 0.12, 0.16) on every colour, so the shape and the ink carry the symbol, not the colour alone.
- Stacks: TileHeight 0.6 (was 0.95). A slab is 0.6 units thick (0.54 at TileScale 0.9); layers stay strictly vertical per cell.
- Tap target: a BoxCollider on each tile's root covers the slab and the emblem (0.66 units tall). A hit resolves to the TileView.
- Materials (D3 as amended by D13): one shared body material per symbol colour and dimmed state (unchanged), one emblem
  material per dimmed state, and one red emblem for flashes. TileView sets materials only when a tile's state changes.
- Scenery: a board plate under the grid and a tray well under the tray slots, both sized from each level (one object each).
- Portrait framing (architect's note on step a): TraySpacing 1.05 (was 1.5), so the tray no longer sets the frame width;
  headroom above the tallest stack is 20 percent of its height (was a fixed 1 unit).
